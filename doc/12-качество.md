# 12. Качество, тестирование, безопасность и эксплуатация

## 12.1. Стратегия качества

Качество обеспечивается на четырёх уровнях:

1. **Детерминизм** — основа доверия к симуляции и реплеям.
2. **Автоматизация** — каждый PR проверяется тестами, линтерами и симуляцией.
3. **Наблюдаемость** — проблемы видны до жалоб игроков.
4. **Процесс** — ревью, Definition of Done, постмортемы.

## 12.2. Пирамида тестов

```text
        ┌──────────────┐
        │ E2E (Playwright) │   ~30 сценариев
        ├──────────────┤
        │ Интеграционные   │   ~200 тестов
        ├──────────────┤
        │ Unit + property  │   ~2 000 тестов
        └──────────────┘
```

### 12.2.1. Unit-тесты

- Формулы урона, брони, скорости, энергии.
- Валидация генома и армии.
- Парсеры и канонизация JSON.
- Кодеки снапшотов.
- Селекторы клиента.
- Утилиты времени, ID, хешей.

Цель покрытия `sim-core`: ≥ 80% строк, 100% критичных веток.

### 12.2.2. Property-based тесты

- Геномы: случайные комбинации органов не должны ронять валидатор.
- Поведение: случайные графы либо валидны, либо дают понятную ошибку.
- Снапшоты: encode → decode → encode даёт тот же байт.
- Матчи: случайные seed и армии не вызывают исключений.
- Баланс: стоимость всегда положительна, HP > 0.

Инструмент: Kotest property testing.

### 12.2.3. Golden-тесты

- Набор из 100 эталонных матчей.
- Для каждого хранится seed, армии, версия правил и хеши тиков.
- При изменении симуляции хеши должны измениться осознанно.
- Diff хешей — обязательный артефакт PR.

### 12.2.4. Интеграционные тесты

- Testcontainers: PostgreSQL, Redis, MinIO.
- Полный цикл: регистрация → геном → армия → матч → результат → реплей.
- Ошибки БД, таймауты, повторные запросы.
- Идемпотентность наград.
- Восстановление после падения worker.

### 12.2.5. E2E-тесты клиента

| Сценарий | Проверка |
|---|---|
| Регистрация и вход | Успех, ошибки, восстановление |
| Создание твари | Добавление органов, валидация, сохранение |
| Редактор поведения | Добавление узлов, ошибка, сохранение |
| Армия | Добавление, расстановка, лимит |
| Очередь и матч | Подбор, подтверждение, старт |
| Зритель | Снапшоты, инспектор, камера |
| Реконнект | Потеря WS, восстановление |
| Реплей | Пауза, перемотка, скорость |
| Настройки | Язык, доступность, графика |

### 12.2.6. Визуальные тесты

- Скриншоты ключевых экранов.
- Сравнение с эталоном, порог 0.1%.
- Отдельные прогоны для тем и масштабов UI.

## 12.3. Детерминизм-харнесс

### 12.3.1. Запуск

```bash
./gradlew :sim:sim-harness:run --args="--matches 1000 --seed 42 --workers 8"
```

### 12.3.2. Проверки

- Одинаковый матч на одном и том же JVM — одинаковый хеш.
- Одинаковый матч на разных JVM (x64, ARM) — одинаковый хеш.
- Одинаковый матч после рестарта — одинаковый хеш.
- Реплей, воспроизведённый через 30 дней, — тот же результат.
- Изменение порядка загрузки контента не влияет.
- Изменение локали не влияет.

### 12.3.3. Инструменты

- `sim-harness` — headless-прогоны.
- `replay-verify` — сравнение реплея с эталоном.
- `hash-diff` — поиск первого расхождения.
- `profile-tick` — профилирование.

### 12.3.4. Политика

- Расхождение — P0-баг.
- PR, меняющий хеши, требует объяснения и обновления golden-файлов.
- На релизной ветке — 10 000 матчей без расхождений.

## 12.4. Нагрузочное тестирование

### 12.4.1. Сценарии

| Сценарий | Нагрузка | Цель |
|---|---|---|
| API чтение | 1 000 RPS | p95 ≤ 150 мс |
| API запись | 200 RPS | p95 ≤ 300 мс |
| Очередь | 5 000 игроков | подбор ≤ 30 с |
| Матчи | 500 одновременных | tick p95 ≤ 8 мс |
| Зрители | 50 на матч | задержка ≤ 500 мс |
| Реконнект | 10% в минуту | восстановление ≤ 3 с |

### 12.4.2. Инструменты

- k6 для API и WebSocket.
- Gatling для сценариев матчей.
- Собственный бот-клиент для зрителей.
- Grafana для наблюдения.

### 12.4.3. Критерии

- Нет ошибок 5xx > 0.5%.
- Нет роста очереди без предела.
- Память не растёт бесконечно.
- CPU не превышает 80% на целевой нагрузке.
- Деградация плавная, без каскадных отказов.

## 12.5. Chaos-тестирование

| Эксперимент | Ожидание |
|---|---|
| Убить sim-worker | Матч аннулирован, рейтинг возвращён |
| Разорвать Redis | Новые матчи не стартуют, активные живы |
| Задержка БД 2 с | Матчи продолжаются, API деградирует |
| Потеря S3 | Реплей недоступен, матч завершён |
| Потеря gateway | Клиенты переподключаются |
| Переполнение диска | Алерт, остановка записи реплеев |
| Утечка памяти | OOM-kill, рестарт, алерт |

## 12.6. Безопасность

### 12.6.1. Модель угроз

| Угроза | Влияние | Меры |
|---|---|---|
| Подмена генома | Нечестная победа | Серверная валидация, хеш |
| Подмена результата | Фальшивый рейтинг | Серверный расчёт, подпись |
| Читы клиента | Преимущество | Клиент не авторитетен |
| DDoS | Недоступность | CDN/WAF, лимиты |
| Кража токена | Доступ к аккаунту | Короткий access, ротация refresh |
| SQL-инъекция | Утечка | jOOQ, параметры |
| XSS | Кража сессии | CSP, санитизация |
| CSRF | Действия от имени | SameSite, токены |
| Спам/оскорбления | Репутация | Фильтры, жалобы, баны |
| Мошенничество с платежами | Потери | Провайдер, вебхуки, антифрод |
| Утечка данных | Репутация | Шифрование, доступ по роли |

### 12.6.2. Меры

- TLS 1.2+, HSTS, secure cookies.
- Argon2id для паролей.
- JWT EdDSA, короткий срок.
- Роли и проверка владения.
- Валидация всех входных данных.
- Ограничение размера и частоты.
- CSP, X-Frame-Options, Referrer-Policy.
- Секреты в Vault/K8s Secrets.
- SAST, DAST, dependency scan в CI.
- Пентест перед релизом.
- Аудит действий администраторов.
- Резервное копирование и шифрование.

### 12.6.3. Реагирование на инциденты

1. Обнаружение (алерт, жалоба, мониторинг).
2. Классификация (P0–P3).
3. Локализация (изоляция сервиса, отзыв токенов).
4. Устранение.
5. Восстановление.
6. Постмортем в течение 5 рабочих дней.
7. Публичное уведомление при утечке персональных данных.

## 12.7. Модерация

### 12.7.1. Объекты

- Никнеймы.
- Имена существ и армий.
- Чат.
- Публичные геномы.
- Аватары.
- Эмоции.

### 12.7.2. Правила

- Запрещены оскорбления, угрозы, спам, реклама, NSFW, политика, разжигание.
- Фильтр слов + ручная проверка.
- Жалоба → очередь модерации → решение → уведомление.
- Санкции: предупреждение, мут 1–7 дней, бан 1–30 дней, перманентный бан.
- Апелляция через поддержку.
- Логи и доказательства (реплей, скриншот).

### 12.7.3. SLA модерации

| Категория | Реакция |
|---|---|
| Угрозы/NSFW | ≤ 1 час |
| Оскорбления | ≤ 24 часа |
| Спам | ≤ 24 часа |
| Апелляция | ≤ 72 часа |

## 12.8. Наблюдаемость

### 12.8.1. Уровни

- **Метрики**: Prometheus, Grafana.
- **Логи**: Loki, структурированный JSON.
- **Трейсы**: OpenTelemetry, Tempo/Jaeger.
- **Ошибки**: Sentry.
- **Продукт**: события, воронки.

### 12.8.2. Дашборды

| Дашборд | Содержание |
|---|---|
| Обзор | CCU, матчи, ошибки, задержки |
| Симуляция | Тики, перегрузки, размер снапшотов |
| Очередь | Размер, время, боты |
| API | RPS, p95, 5xx, лимиты |
| БД | Connections, slow queries, репликация |
| Экономика | Начисления, аномалии, покупки |
| Баланс | Win rate, pick rate, длительность |
| Клиент | Web Vitals, ошибки, версии |

### 12.8.3. SLO

| SLO | Цель | Окно |
|---|---|---|
| Доступность API | 99.9% | 30 дней |
| Успешный старт матча | 99.5% | 7 дней |
| Tick p95 | ≤ 8 мс | 7 дней |
| Время в очереди p95 | ≤ 30 с | 7 дней |
| Ошибки клиента | ≤ 1% сессий | 7 дней |
| Восстановление после сбоя | ≤ 60 мин | инцидент |

### 12.8.4. Алерты

- Error budget > 50% — предупреждение.
- Error budget > 80% — заморозка релизов.
- Критические — PagerDuty/Telegram.
- Дежурство 24/7 после релиза.

## 12.11. Definition of Done

Функция считается готовой, если:

1. Требование реализовано и соответствует критериям приёмки.
2. Есть unit- и интеграционные тесты.
3. Пройдены линтеры и статический анализ.
4. Нет критичных уязвимостей.
5. Обновлена документация и схемы.
6. Проверено на staging.
7. Метрики и логи добавлены.
8. Проведено ревью кода.
9. Нет регрессий в golden-тестах (или изменения объяснены).
10. Функция доступна за feature flag, если рискованна.

## 12.12. Постмортем

Шаблон:

- Что произошло.
- Влияние на пользователей.
- Хронология.
- Корневая причина.
- Что сработало.
- Что не сработало.
- Действия с владельцами и сроками.
- Как предотвратить повтор.

Постмортем обязателен для P0/P1 и утечек данных.

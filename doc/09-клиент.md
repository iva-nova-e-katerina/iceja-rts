# 09. Клиент (браузерный, 2D)

## 9.1. Решение

Клиент — **браузерное 2D-приложение** с ортографической проекцией **top-down**. Одна и та же проекция используется в лаборатории, планировщике, бою и реплее: существо, собранное в конструкторе, выглядит в бою так же, как на столе.

### 9.1.1. Стек

| Слой | Технология | Версия | Назначение |
|---|---|---|---|
| Язык | TypeScript | 5.7+ | Строгая типизация, общие схемы |
| Рендер | PixiJS | 8.x | WebGL2/WebGPU, спрайты, батчинг, фильтры |
| UI | React | 19.x | Панели, формы, редакторы |
| Состояние | Zustand | 5.x | Локальное состояние UI |
| Серверные данные | TanStack Query | 5.x | Кэш REST, инвалидация |
| Граф поведения | React Flow | 12.x | Визуальный редактор |
| Сборка | Vite | 6.x | Dev-server, code splitting |
| Стили | CSS Modules + tokens | — | Темы, изоляция |
| Бинарные схемы | FlatBuffers TS | 24.x | Снапшоты и реплеи |
| Звук | Howler.js | 2.x | Музыка, SFX, позиционирование |
| i18n | i18next + ICU | — | Локализация |
| Тесты | Vitest, Playwright | — | Unit, e2e |
| Ошибки | Sentry | — | Диагностика |
| Аналитика | собственный клиент + OTel | — | События, метрики |

### 9.1.2. Почему не Phaser / Godot Web / Unity WebGL

- **Phaser** даёт готовые сцены и физику, но хуже подходит для сложного React-интерфейса конструктора и кастомного рендера.
- **Godot Web** — большой бандл, отдельный UI-стек, сложнее интеграция с веб-формами.
- **Unity WebGL** — тяжёлый старт, большой размер, ограничения памяти вкладки.
- **PixiJS + React** — минимальный контроль над всем, лучший размер, нативная кодогенерация схем, удобная работа со слоями и эффектами.

### 9.2.1. Правила

- React не рендерит игровое поле; поле — `<canvas>` PixiJS.
- React-компоненты не читают снапшоты напрямую; они подписаны на производные селекторы.
- Снапшоты не хранятся в React-состоянии целиком; только агрегаты для HUD.
- Рендер-цикл не зависит от React-рендера.
- Все сетевые ошибки имеют пользовательское сообщение и retry.
- Все фиче-модули изолированы; общие типы — в `shared`.

## 9.3. Рендер

### 9.3.1. Слои сцены

| Слой | Содержимое | Порядок |
|---|---|---|
| `ground` | Тайлы поверхности, автопереходы | 0 |
| `decals` | Кровь, кислота, следы, трупы | 10 |
| `shadows` | Тени существ и снарядов | 20 |
| `entities` | Существа, ульи, турели | 30 |
| `projectiles` | Снаряды | 40 |
| `vfx` | Частицы, вспышки, ауры | 50 |
| `fog` | Туман войны (опционально) | 60 |
| `overlay` | HP-бары, иконки состояний, отладка | 70 |
| `ui` | React-интерфейс поверх canvas | DOM |

### 9.3.2. Камера

- Ортографическая, без перспективы.
- Масштаб: 0.5–3×, базовый 1× = 64 px на метр.
- Панорама: WASD, стрелки, drag средней/правой кнопкой, edge-scroll (опционально).
- Зум: колесо к курсору.
- Следование: клик по существу или кнопка «следить».
- Ограничение по границам карты с плавным отскоком.
- Тряска камеры: только для крупных событий, отключаемая.

### 9.3.3. Координаты

- Мир: миллиметры, как на сервере.
- Экран: `screen = (world - camera) * scale`.
- Отрисовка в пикселях, округление к целому для спрайтов.
- Сортировка по `y` для псевдоглубины (кто ниже — рисуется позже).
- Углы: сервер в 1/65536 оборота, клиент конвертирует в радианы.

### 9.3.4. Интерполяция

- Клиент держит буфер снапшотов 100 мс (3 снапшота).
- Позиция существа интерполируется между двумя снапшотами.
- Угол интерполируется по кратчайшей дуге.
- HP и энергия — линейно или мгновенно (по настройке).
- При потере снапшота — экстраполяция не более 200 мс, затем «заморозка».
- При реконнекте — сброс буфера и ключевой кадр.

### 9.3.5. Батчинг и производительность

- Все спрайты — в атласах, `PIXI.Sprite` с общим `BaseTexture`.
- Частицы — `ParticleContainer`.
- Тайлы — `Tilemap`/`CompositeTilemap` или один меш.
- Сортировка сущностей — раз в кадр, не чаще.
- Culling: не рисовать за пределами камеры + 2 экрана.
- LOD: на минимальном зуме упрощённые спрайты и без теней.
- Цель: ≤ 300 draw calls, ≤ 5 000 спрайтов, 60 FPS.

### 9.3.6. Пикинг

- Клик по существу — hit-test по кругу/спрайту.
- Приоритет: существа > ульи > снаряды > земля.
- Hover подсвечивает силуэт и показывает имя.
- В конструкторе — пикинг по сокетам и органам.

## 9.4. Существа в 2D

### 9.4.1. Модульная сборка

- Каждый орган — спрайт с пивотом, смещением и сокетом.
- Контейнер существа: тело + органы, поворачивается целиком по направлению.
- Органы крепятся в локальных координатах сокета.
- Зеркальные органы отражаются по X.
- Порядок отрисовки: ноги → тело → броня → оружие → голова → эффекты.
- Масштаб частей зависит от размера шасси.

### 9.4.2. Анимация

- Процедурная, без скелета в MVP:
  - дыхание: лёгкое масштабирование тела;
  - ходьба: ноги качаются по синусоиде с фазой от скорости;
  - атака: выпад/замах по таймлайну оружия;
  - получение урона: вспышка и короткий сдвиг;
  - смерть: падение, затухание, декаль.
- Параметры анимации задаются в `part.json` (амплитуда, частота, фаза).
- Позже — скелетная анимация (Spine) для крупных существ.

### 9.4.3. Визуальные состояния

| Состояние | Визуал |
|---|---|
| `moving` | Анимация ног, пыль |
| `attacking` | Вспышка оружия, след |
| `stunned` | Искры, покачивание |
| `burning` | Огонь, дым |
| `poisoned` | Зелёные пузыри |
| `bleeding` | Капли, декаль |
| `healing` | Мягкое свечение |
| `burrowed` | Полупрозрачный силуэт, земля |
| `fleeing` | Иконка страха |
| `dead` | Труп, затухание |

### 9.4.4. Палитры и косметика

- Палитра применяется к телу и акцентам через тинт и маски.
- Узоры (пятна, полосы) — шейдерный слой или отдельный спрайт.
- Косметика не меняет силуэт настолько, чтобы путать роль.
- В ranked косметика видна всем; отключаемая опция «стандартные цвета».

### 9.4.5. Читаемость

- Силуэт должен читаться на минимальном зуме.
- Роль определяется формой, а не только цветом.
- HP-бар над существом: тонкий, с цветом стороны.
- Иконки состояний — до 3, остальные в инспекторе.
- Дальность атаки показывается при наведении/выборе.

## 9.5. Мир в 2D

### 9.5.1. Тайлы

- Размер тайла: 64 × 64 px при 1×.
- Набор: 47-тайловый blob-автотайл для переходов.
- Слои: базовая поверхность, детали, опасности.
- Анимация: вода, кислота, огонь — 4–8 кадров.
- Карта 128 × 128 = 16 384 тайла; рендерится через tilemap.

### 9.5.2. Декор

- Камни, кости, растения, обломки — без коллизий.
- Размещаются детерминированно по seed карты.
- Не перекрывают важные объекты.
- Отключаются на минимальных настройках.

### 9.5.3. Туман войны

- По умолчанию выключен: игрок — зритель.
- Опционально: клиент вычисляет видимость по позициям союзных существ и препятствиям.
- Визуал: тёмная маска с мягкими краями, анимация «дыхания».
- Не влияет на получаемые данные (сервер всё равно отправляет всё).
- Для стримеров — режим «туман соперника» (Could).

### 9.5.4. Мини-карта

- 128 × 128 px, масштабируется.
- Тайлы упрощённые, существа — точки цвета стороны.
- Ульи — крупные иконки.
- Рамка камеры.
- Клик — перемещение камеры.
- В реплее — тепловые карты по слоям.

## 9.7. UI/UX принципы

1. **Сначала существо.** Главный объект на экране — творение игрока, а не интерфейс.
2. **Объясняй цифры.** Каждая характеристика имеет подсказку с формулой.
3. **Не прячь ошибки.** Валидация видна всегда.
4. **Один экран — одна задача.** Конструктор не перегружен армией.
5. **Тёмная тема по умолчанию.** Светлая — опция.
6. **Анимация помогает, а не мешает.** Всё отключаемо.
7. **Клавиатура.** Основные действия доступны без мыши.
8. **Консистентность.** Одни и те же иконки для органов и ролей везде.
9. **Прогрессивное раскрытие.** Новичок видит простое, опытный — детали.
10. **Никаких тёмных паттернов.** Нет таймеров на покупку, нет искусственного дефицита.

### 9.8.2. Конвейер

1. Художник рисует орган в Aseprite/Photoshop.
2. Экспорт в PNG с прозрачностью.
3. Разметка пивота и сокетов в `part.json`.
4. Сборка атласа через скрипт.
5. Валидация: размеры, пивоты, дубликаты.
6. Публикация в CDN с версией.

### 9.8.3. Ограничения

- Атлас ≤ 4096 × 4096.
- Один орган ≤ 512 × 512.
- Общий размер ассетов для первой загрузки ≤ 15 МБ.
- Ленивая загрузка звука и косметики.
- Все ассеты имеют версию и хеш.

### 9.8.4. Стиль

- Тёмный биопанк: влажные поверхности, биолюминесценция, кость, хитин.
- Палитра: глубокий сине-зелёный фон, тёплые акценты, неоновый циан.
- Силуэты читаемые, без мелких деталей на минимальном зуме.
- Кровь — тёмная жидкость, без реализма; рейтинг 12+.
- Интерфейс — приборная панель лаборатории.

## 9.9. Звук

- Музыка: эмбиент лаборатории, бой — ритмичная, но не навязчивая.
- SFX: атаки, попадания, смерть, способности, ульи, UI.
- Позиционное аудио: только для событий в камере.
- Приглушение при потере фокуса вкладки.
- Отключаемые категории.
- Субтитры для ключевых событий.
- Autoplay: звук включается после первого клика.

## 9.10. Сеть и состояние

### 9.10.1. REST-клиент

- Обёртка над `fetch` с таймаутом 10 с.
- Автоматическое обновление токена при 401 (один раз).
- Retry с экспоненциальной задержкой для 5xx и сети (3 попытки).
- Отмена запросов при уходе с экрана.
- Кэш каталога в IndexedDB с версией.

### 9.10.2. WebSocket-клиент

- Подключение по одноразовому тикету `POST /ws/ticket`, access-токен не попадает в URL.
- Heartbeat каждые 20 с.
- Очередь исходящих сообщений при обрыве.
- Реконнект: 1, 2, 4, 8, 16 с, затем 30 с.
- При реконнекте в матче — `match_resume`.
- При реконнекте в лобби — восстановление очереди.
- Логирование всех типов сообщений (без токенов).

### 9.10.3. Состояние матча

- `MatchView` хранит:
  - последний ключевой кадр;
  - буфер снапшотов (3–5);
  - производные: HP сторон, численность, таймер;
  - выбранное существо;
  - камеру.
- React получает агрегаты через `useSyncExternalStore`.
- Тяжёлые данные (существа) живут в render-слое, не в React.

### 9.10.4. Оптимистичные обновления

- Только для лаборатории и армии (локальный черновик).
- При ошибке сервера — откат и сообщение.
- Матч и экономика — без оптимистичных обновлений.

## 9.11. Производительность

### 9.11.1. Бюджеты

| Метрика | Цель |
|---|---|
| FPS | 60 на средних, 30 на минимальных |
| Время кадра | ≤ 16.6 мс |
| JS-работа на кадр | ≤ 6 мс |
| Draw calls | ≤ 300 |
| Спрайты | ≤ 5 000 |
| Память | ≤ 512 МБ |
| Первая загрузка | ≤ 5 с на 10 Мбит/с |
| Размер бандла | ≤ 1.5 МБ gzip (без ассетов) |
| Реконнект | ≤ 3 с |

### 9.11.2. Приёмы

- Code splitting по экранам.
- Ленивая загрузка PixiJS-сцены боя.
- Атласы и `ParticleContainer`.
- Пул объектов для эффектов.
- `requestAnimationFrame` с фиксированным шагом рендера.
- Отключение рендера при скрытой вкладке.
- Web Worker для декодирования больших реплеев (Should).
- Избегать реаллокаций в цикле интерполяции.
- Профилирование через Chrome DevTools и PixiJS devtools.

### 9.11.3. Деградация

| Условие | Действие |
|---|---|
| FPS < 45 в течение 3 с | Отключить тени и часть частиц |
| FPS < 30 | Упростить спрайты, уменьшить буфер |
| Нет WebGL2 | Экран «браузер не поддерживается» |
| Мало памяти | Предложить закрыть другие вкладки |
| Медленная сеть | Снизить качество ассетов, чаще ключевые кадры |

## 9.12. Ошибки и восстановление

- Глобальный Error Boundary с экраном «что-то пошло не так» и кнопкой перезагрузки.
- Ошибки сети — тосты с retry.
- Ошибки валидации — inline, у конкретного поля.
- Потеря соединения в матче — оверлей «переподключение», матч продолжается.
- Матч аннулирован — сообщение, возврат рейтинга, кнопка «в очередь».
- Ошибка загрузки ассетов — повтор с CDN, затем упрощённый режим.
- Sentry с `release`, `userId` (хеш), `matchId`, но без геномов и чата.

## 9.13. Безопасность клиента

- Токены хранятся в памяти + refresh в `HttpOnly` cookie (предпочтительно) или защищённом хранилище.
- Нет секретов в бандле.
- CSP: `default-src 'self'`, явные домены для CDN, Sentry, OAuth.
- Запрет `eval`, `new Function`.
- Санитизация пользовательского текста (ник, чат, имя генома).
- Ссылки открываются с `rel="noopener noreferrer"`.
- Защита от clickjacking: `X-Frame-Options: DENY`.
- Сторонние скрипты только с согласия и по минимуму.

## 9.14. Доступность

- Все интерактивные элементы доступны с клавиатуры.
- Фокус видим, порядок логичный.
- ARIA-атрибуты для меню, диалогов, табов.
- Контраст текста ≥ 4.5:1.
- Не полагаться только на цвет: иконки + текст.
- Настройка «снизить движение»: отключить тряску, вспышки, анимации фона.
- Субтитры для событий.
- Масштаб UI 80–150%.
- Экранные читалки: меню и формы, но не игровое поле (описано в помощи).

## 9.15. Локализация

- Все строки в JSON/ICU, ключи стабильны.
- Плюрализация через ICU.
- Форматирование чисел, дат, валюты.
- Длинные строки не ломают кнопки (тест псевдолокализации +30%).
- Языки на запуске: русский, английский.
- Переключение без перезагрузки.
- Названия органов переводятся, но ID остаются.

## 9.17. Сборка и деплой

- `vite build` → статика.
- Деплой в CDN/S3 + invalidation.
- Версия в `version.json`, проверка обновления при загрузке.
- Service Worker для оболочки и ассетов (PWA, Should).
- Feature flags с сервера.
- Канареечный релиз 5% → 25% → 100%.
- Rollback — предыдущая статика.
- Мониторинг: Sentry, Web Vitals, собственные метрики.

## 9.18. Ограничения браузера и обходы

| Ограничение | Решение |
|---|---|
| Autoplay заблокирован | Включать звук после первого клика |
| Вкладка в фоне тормозит | Пауза рендера, догон при возврате |
| Ограничение памяти | Ленивая загрузка, освобождение сцен |
| Safari WebGL | Тестировать, избегать редких расширений |
| WebGPU не везде | Фолбэк на WebGL2 |
| Потеря контекста | Восстановление сцены, перезагрузка атласов |
| Полноэкранный режим | Кнопка, обработка Escape |
| Высокий DPI | `resolution = devicePixelRatio`, ограничение 2× |
| Блокировщики | Не полагаться на сторонние скрипты |

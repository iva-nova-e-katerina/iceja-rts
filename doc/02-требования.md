# 02. Требования

## 2.1. Соглашения

- **Must** — входит в MVP, без этого релиз невозможен.
- **Should** — входит в бету, может быть перенесено без разрушения продукта.
- **Could** — после релиза.
- **Не входит** — явно исключено из текущей версии.
- Все идентификаторы стабильны; удаление требования допускается только с записью в журнале изменений.
- Критерии приёмки формулируются в терминах наблюдаемого поведения, а не реализации.

## 2.4. Ограничения и допущения

### 2.4.1. Ограничения

- Серверная симуляция должна работать на JVM без нативных зависимостей, влияющих на детерминизм.
- Клиент не хранит авторитетное состояние боя.
- Браузерный клиент ограничен памятью вкладки и политиками autoplay.
- Матч не может длиться дольше 15 минут в любом режиме.
- Одна сторона — не более 40 существ.
- Стоимость армии — не более 6000 BM в ranked.
- Все боевые параметры должны быть объяснимы игроку.

### 2.4.2. Допущения

- У игроков есть стабильный интернет ≥ 5 Мбит/с.
- Основная аудитория — desktop.
- Онлайн на старте достаточен для очереди 1×1 в одном регионе.
- Команда имеет опыт Kotlin и TypeScript.
- Арт-контент создаётся процедурно из модульных частей, а не вручную для каждой твари.
- Баланс будет итеративным; первая версия не обязана быть идеальной.

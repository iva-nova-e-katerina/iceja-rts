# 05. Симуляция

## 5.1. Назначение

Документ описывает детерминированную модель боя: мир, сущности, порядок обновления, движение, восприятие, бой, эффекты, цели и завершение матча. Все правила обязательны для `sim-core` и не зависят от клиента.

## 5.2. Базовые единицы

| Величина | Единица | Тип | Примечание |
|---|---|---|---|
| Время | тик | `int32` | 30 тиков = 1 с |
| Длительность тика | 1/30 с | константа | Не хранится как float |
| Позиция | миллиметр | `int32` | Карта 128 000 × 128 000 мм |
| Скорость | мм/тик | `int32` | 1000 мм/тик = 30 м/с |
| Угол | 1/65536 оборота | `uint16` | 0 = вправо, 16384 = вниз |
| HP, энергия | целое | `int32` | Внутренние единицы |
| Масса | грамм | `int32` | Для формул |
| Радиус | миллиметр | `int32` | Коллизии |
| Урон | целое | `int32` | Внутренние единицы |
| Дальность | миллиметр | `int32` | Сравнение по квадрату |
| RNG | xoshiro128** | `uint32[4]` | Отдельные потоки |

Мир не использует `float`/`double`. Для расстояний и нормализации применяется целочисленный квадратный корень (`isqrt`) или предвычисленные таблицы направлений. Операции деления — только с явным округлением (toward zero или floor) и фиксированным правилом.

## 5.3. Детерминизм

### 5.3.1. Обязательные правила

1. Один и тот же вход (`seed`, геномы, армии, карта, ruleset) даёт один и тот же хеш на каждом тике.
2. Обход сущностей — по возрастанию `entityId`, без итерации по `HashMap`/`HashSet`.
3. Все коллекции, влияющие на симуляцию, имеют стабильный порядок.
4. Никаких системных часов, `Random`, `UUID`, `hashCode` объектов, `Object.identityHashCode`.
5. Никаких параллельных потоков внутри матча.
6. Все события применяются в детерминированном порядке.
7. Деление округляется единообразно; переполнение контролируется.
8. Строки не влияют на симуляцию, кроме предварительно вычисленных хешей.
9. Порядок загрузки контента фиксирован; каталог сортируется по ID.
10. Версия правил и каталога входит в хеш матча.

### 5.3.2. Хеширование

- Каждый тик считается `xxHash64` от канонического бинарного представления состояния.
- Хеш пишется в лог и реплей.
- В тестах сравниваются хеши на тиках 1, 30, 300, 9000, финальный.
- Расхождение — блокирующий баг.

### 5.3.3. PRNG

- Алгоритм: xoshiro128**.
- Состояние: 4 × `uint32`.
- Seed: 128 бит из `matchId` + серверный секрет.
- Потоки: `world`, `combat`, `ai`, `loot`, `mutation` — независимые состояния, чтобы изменения в одной системе не сдвигали другую.
- Запрос случайности фиксирован: `nextInt(bound)` с rejection sampling, без modulo bias.

## 5.4. Мир

### 5.4.1. Размер и сетка

- Карта: 128 × 128 метров.
- Сетка: 1 м, 128 × 128 клеток.
- Слои: проходимость, тип поверхности, укрытие, опасность, ресурсы, зоны.
- Высоты нет: мир плоский, top-down.
- Границы: непроходимы.

### 5.4.2. Типы поверхности

| Тип | Проходимость | Эффект |
|---|---|---|
| `GROUND` | Да | Базовая скорость |
| `SAND` | Да | −10% скорости |
| `MUD` | Да | −20% скорости, +10% к стоимости поворота |
| `WATER` | Да (кроме тяжёлых) | −30% скорости, тушение горения |
| `ACID` | Да | Урон 5/с, коррозия брони |
| `ROCK` | Нет | Препятствие, укрытие |
| `WALL` | Нет | Препятствие, полное укрытие |
| `NEST` | Да | Зона улья, лечение 1% HP/с |
| `DEPLOY` | Да | Зона развертывания |

### 5.4.3. Укрытие

- Клетки `ROCK`/`WALL` дают укрытие.
- Если между стрелком и целью есть клетка укрытия, но линия видимости проходит, цель получает бонус к уклонению от дальних атак.
- Укрытие не блокирует полностью, если стрелок стоит вплотную.
- Расчёт: `coverBonus = 20%`, если линия пересекает укрытие и расстояние > 5 м.

### 5.4.4. Опасности

- Кислота наносит урон и снижает броню на 1 ед./с (до 50%).
- Огонь распространяется по клеткам с горючей поверхностью (опционально для карт).
- Электричество в воде усиливается.

### 5.4.5. Ресурсы

- Нейтральные «нектарные узлы»: 4 шт. на карте.
- Существо с органом `NectarCrop` может собирать нектар, восстанавливая энергию.
- Узел имеет запас 5000 единиц, восстанавливается 10/с.
- Сбор требует нахождения в радиусе 2 м и действия `Harvest`.

### 5.4.6. Симметрия карт

- Карты зеркальные (осевая или центральная симметрия).
- Проверка: для каждой проходимой клетки существует симметричная проходимая.
- Ресурсные узлы и ульи симметричны.
- Генератор карт использует seed, но финальная карта валидируется и хешируется.

## 5.5. Сущности

### 5.5.1. Типы

| Тип | Описание |
|---|---|
| `CREATURE` | Существо игрока или бота |
| `PROJECTILE` | Снаряд |
| `HIVE` | Улей (статичная цель) |
| `TURRET` | Турель (режим осады) |
| `RESOURCE` | Нектарный узел |
| `CORPSE` | Труп (объект, не цель) |
| `DECAL` | Визуальный след (не в симуляции) |

### 5.5.2. Идентификаторы

- `entityId`: `uint32`, монотонный, начиная с 1.
- ID выдаются в порядке создания: сначала ульи, затем существа по сторонам и индексам армии.
- ID не переиспользуются.
- `playerId` (0/1) и `teamId` (0/1) фиксированы.

### 5.5.3. Компоненты существа

| Компонент | Поля |
|---|---|
| `Identity` | entityId, ownerId, genomeVersionId, name |
| `Transform` | x, y, angle, radius, mass |
| `Vitals` | hp, maxHp, energy, maxEnergy, heat, stamina |
| `Locomotion` | vx, vy, speed, accel, turnRate, mode |
| `Combat` | weapons[], cooldowns[], targetId, attackPhase |
| `Armor` | kinetic, thermal, acid, electric, toxic |
| `Senses` | visionRange, visionAngle, hearing, smell |
| `Brain` | behaviorState, blackboard, lastDecisionTick |
| `Status` | effects[] |
| `Economy` | hunger, nectar, reproductionCooldown |
| `Flags` | alive, burrowed, flying, stunned, fleeing |

## 5.6. Порядок тика

### 5.6.1. Общая схема

```
tick:
  applyPendingCommands()      // только тик 0
  updateSensors()             // все существа по ID
  updateAI()                  // только существа с (id + tick) % 3 == 0
  buildIntents()              // все существа
  resolveMovement()           // интеграция + коллизии
  resolveCombat()             // атаки и снаряды
  applyDamageAndEffects()     // очередь событий
  updateEconomy()             // энергия, голод, ресурсы
  updateObjectives()          // ульи, зоны, таймер
  removeDead()                // трупы, снаряды
  emitEvents()
  hashState()
```

### 5.6.2. Очерёдность внутри фазы

- Существа: по `entityId`.
- Снаряды: по `entityId`.
- События урона: `(targetId, sourceId, eventSeq)`.
- Эффекты: по `effectId`, затем по источнику.

### 5.6.3. AI-расписание

- AI обновляется каждые 3 тика.
- Условие: `entityId % 3 == tick % 3`.
- Это распределяет нагрузку и сохраняет детерминизм.
- Решение действует до следующего обновления; намерения пересчитываются каждый тик.

## 5.7. Восприятие

### 5.7.1. Зрение

- Конус: `visionAngle` (обычно 120–270°), радиус `visionRange`.
- Проверка: расстояние, угол, линия видимости по сетке.
- Линия видимости: DDA по клеткам, стены блокируют, укрытия не блокируют, но дают бонус.
- Существа за стеной не видны.
- Свойства: `visibleEnemies`, `visibleAllies`, `visibleResources`.

### 5.7.2. Слух

- Радиус `hearing`, не зависит от стен, но стены снижают на 50%.
- Источники: выстрелы, взрывы, смерть, бег.
- Даёт приблизительную позицию с ошибкой ±3 м.

### 5.7.3. Запах/хеморецепция

- Радиус `smell`, игнорирует стены.
- Даёт направление на ближайшего врага, но не точную позицию.
- Не работает на летающих/подземных без соответствующего органа.

### 5.7.4. Память

- Blackboard хранит последнюю известную позицию цели и тик.
- Время жизни памяти: 5–20 с в зависимости от органа.
- Если цель пропала, существо движется к последней позиции.

### 5.7.5. Скрытность

- `Camouflage` снижает радиус обнаружения на 50%, если существо не двигалось и не атаковало.
- После атаки скрытность снимается на 3 с.

## 5.8. Движение

### 5.8.1. Модель

- Кинематическое движение без инерции вращения.
- Существо имеет желаемое направление и скорость.
- Ускорение ограничено, поворот ограничен `turnRate`.
- Коллизия: круг против клеток и других существ.
- Летающие существа игнорируют наземные препятствия, но не стены выше 3 м.

### 5.8.2. Навигация

- Сетка 1 м, 8 направлений.
- A* с детерминированным tie-break по `(f, g, cellIndex)`.
- Кэш путей на 2 секунды; инвалидация при изменении препятствий (в ranked препятствия статичны).
- Для групп — flow field к общей цели, пересчёт раз в 1 с.
- Локальное расталкивание: приоритет по `entityId`, сила пропорциональна пересечению.
- Застревание: если существо не сдвинулось на 0.2 м за 2 с, пересчёт пути; если 5 с — выбор новой цели.

### 5.8.3. Скорости

- Базовая скорость: 0.5–8 м/с.
- Модификаторы: поверхность, статусы, масса, усталость.
- Ускорение: 2–20 м/с².
- Поворот: 90–720 °/с.
- Толпа: при 3+ существах в радиусе 1 м скорость снижается на 10% (опционально).

### 5.8.4. Коллизии

- Существо — круг радиусом 0.2–1.5 м.
- Стены — клетки, пересечение круга с клеткой.
- Разрешение: выталкивание по минимальной оси, порядок по ID.
- Существа не проходят сквозь друг друга, но могут слегка перекрываться при массовом столкновении.
- Ульи — круг радиусом 4 м, непроходимы.

## 5.9. Бой

### 5.9.1. Атака

1. Выбор цели (из поведения).
2. Проверка дистанции и угла.
3. Проверка кулдауна и энергии.
4. Запуск анимации/фазы замаха (`windup`).
5. Нанесение урона или создание снаряда в момент `release`.
6. Откат (`recovery`).

### 5.9.2. Ближний бой

- Дуга атаки: 60–180°.
- Радиус: сумма радиусов + длина оружия.
- Попадание: цель в дуге и в радиусе.
- Можно задеть нескольких, если оружие имеет `cleave`.
- Дружественный урон: по умолчанию 0, кроме особых способностей.

### 5.9.3. Дальний бой

- Снаряд — сущность с позицией, скоростью, временем жизни, уроном, типом.
- Полёт: линейный, без гравитации (кроме `mortar`).
- Коллизия: круг снаряда против существ и стен.
- Дружественный урон: выключен, если не указано иное.
- Промах: снаряд летит в точку с ошибкой, зависящей от точности и движения цели.
- Рикошет: только для специальных органов.

### 5.9.4. Точность и уклонение

```
distFactor = clamp(1.0, 0.4, distance / effectiveRange)
evasion = baseEvasion + speed * 0.1 + sizeBonus + coverBonus
hitChance = clamp(0.05, 0.95, accuracy / (accuracy + evasion * distFactor))
```

- `accuracy` — характеристика оружия (10–100).
- `baseEvasion` — от органов (0–30).
- `sizeBonus` — крупные цели легче поразить (+10…+30).
- `coverBonus` — 0–20.
- Бросок: `rng.combat.nextInt(10000) < hitChance * 10000`.

### 5.9.5. Урон

```
armorEff = max(0, armor * (100 - penetration) / 100)
reduction = armorEff / (armorEff + 100)
damage = baseDamage * (1 - reduction) * typeMultiplier * criticalMultiplier
```

- Броня: 0–200 (эффективно до 80% снижения).
- Пробитие: 0–100.
- Типы: `KINETIC`, `PIERCING`, `THERMAL`, `ACID`, `ELECTRIC`, `TOXIC`.
- Множители по типам брони: 0.5–1.5.
- Минимальный урон: 1, если атака попала.
- Критический удар: 5–25% шанс, ×1.5–2.0, зависит от органов.

### 5.9.6. Статусы

| Статус | Эффект | Длительность | Стаки |
|---|---|---|---|
| `BURNING` | 5–20 урона/с, снимает регенерацию | 3–8 с | Нет |
| `BLEEDING` | 3–10 урона/с, усиливается при движении | 5–15 с | 3 |
| `POISONED` | 2–8 урона/с, снижает лечение | 10–30 с | 5 |
| `STUNNED` | Не двигается и не атакует | 0.5–3 с | Нет |
| `SLOWED` | −20…−60% скорости | 2–8 с | Нет |
| `FEAR` | Бежит от источника | 1–5 с | Нет |
| `RAGE` | +20% урона, −20% защиты | 5–15 с | Нет |
| `CORRODED` | −10…−50% брони | 10–30 с | 5 |
| `REGENERATING` | +1…+5% HP/с | 5–20 с | Нет |
| `BURROWED` | Невидим, не может атаковать | До действия | Нет |

- Статусы хранятся списком, обновляются в конце тика.
- Один и тот же статус обновляет длительность, а не добавляет новый, если не стакается.
- Смерть снимает все статусы.

### 5.9.7. Лечение

- Регенерация: `regenPerSecond` от органов, не работает при горении/кровотечении.
- Нектар: +энергия, затем HP.
- Лечение улья: +1% HP/с в зоне.
- Ограничение: не выше `maxHp`.

### 5.9.8. Смерть

- HP ≤ 0 → `alive = false`.
- Труп остаётся на 30 с, может быть съеден.
- Смерть создаёт событие `death` с причиной и источником.
- Существо не исчезает мгновенно, чтобы клиент показал анимацию.

## 5.10. Энергия и экономика существа

### 5.10.1. Энергия

- Максимум: 100–2000.
- Регенерация: 1–50/с.
- Расход: поддержание (0.5–20/с), движение (0–5/с), атаки (5–100 за атаку), способности.
- При 0 энергии: скорость −50%, атаки недоступны, кроме базовой.
- Голод: если энергия 0 дольше 10 с, HP падает на 1%/с.

### 5.10.2. Нектар

- Сбор: 10–50 единиц/с в зависимости от органа.
- Хранение: 0–500.
- Трата: восстановление энергии 1:2, HP 1:4.
- Узел истощается, но восстанавливается.

### 5.10.3. Трупы

- Труп — источник питания для `Scavenger`.
- Съедение: 20–100 энергии за 2 с.
- Труп исчезает через 30 с или после съедения.

### 5.10.4. Размножение

- Только в песочнице, выживании и осаде (по умолчанию).
- Требует органа `Ovipositor`, энергии ≥ 50% и кулдауна 30–120 с.
- Потомок: копия генома с возможными мутациями (только в песочнице).
- В ranked размножение отключено.
- Лимит потомков на матч: 10 (в режимах, где разрешено).

## 5.11. Ульи и цели

### 5.11.1. Улей

- HP: 3000 (дуэль), 5000 (осада).
- Радиус: 4 м.
- Броня: 50 по всем типам.
- Не двигается, не атакует (кроме осады).
- Зона лечения: радиус 10 м, +1% HP/с союзникам.
- Уничтожение — немедленная победа атакующей стороны.

### 5.11.2. Зоны

- `DEPLOY`: стартовая зона 20 × 20 м вокруг улья.
- `NEST`: радиус 10 м, лечение.
- `OBJECTIVE`: нейтральная зона в центре (для режима «контроль»).
- `HAZARD`: кислота/огонь.

### 5.11.3. Режим «Контроль» (Could)

- Три точки на карте.
- Сторона, удерживающая 2 из 3 в течение 30 с, получает очки.
- Победа по очкам или уничтожению улья.
- Не входит в MVP.

## 5.12. Условия победы

### 5.12.1. Дуэль

1. Улей противника уничтожен → победа.
2. Все боеспособные существа противника мертвы → победа.
3. Время вышло:
   - больше HP улья → победа;
   - при равенстве — больше суммарного HP существ;
   - при равенстве — больше нанесённого урона;
   - при равенстве — ничья.
4. Одновременное уничтожение обоих ульев → ничья.

### 5.12.2. Осада

- Атакующий: уничтожить улей.
- Защитник: продержаться до конца таймера.
- Волны атакующего: 3 волны, интервал 90 с, бюджет волны 2000 BM.

### 5.12.3. Выживание

- Волны идут, пока армия жива.
- Победа: пройти все волны.
- Поражение: все существа мертвы.
- Счёт: волны + убийства + выжившие.

### 5.12.4. Таймеры

- Дуэль: 8 минут + 2 минуты овертайм.
- Осада: 10 минут.
- Выживание: 15 минут.
- Песочница: без ограничения.
- По истечении — принудительное завершение с расчётом результата.

## 5.14. Производительность симуляции

### 5.14.1. Структуры данных

- Существа: плотный массив `Array<Creature>` с индексом `creatureIndex`; глобальный `entityId` отображается через `IntArray idToIndex`. Это нужно потому, что ID общие для ульев, существ и снарядов.
- Снаряды: массив с свободными слотами и отдельным `idToIndex`.
- Пространственный индекс: uniform grid 4 × 4 м, массивы ID.
- Клетки: плоские массивы `ByteArray`/`IntArray`.
- Blackboard: `LongArray` ключей + `IntArray` значений фиксированного размера.

### 5.14.2. Бюджет

| Операция | Бюджет на 80 существ |
|---|---|
| Восприятие | 1.5 мс |
| AI | 1.5 мс |
| Движение | 1.5 мс |
| Бой | 1.5 мс |
| Эффекты | 0.5 мс |
| Снапшот | 0.5 мс |
| Прочее | 1.0 мс |
| Итого p95 | ≤ 8 мс |

### 5.14.3. Оптимизации

- Early exit для дальних существ.
- Кэш линий видимости на 3 тика.
- Кэш путей и flow field.
- Отсечение AI по расстоянию до врагов.
- Пул объектов для снарядов и событий.
- Без аллокаций в горячем цикле (цель: ≤ 1 МБ/с на матч).
- Профилирование через JMH и async-profiler.

## 5.15. Ограничения и краевые случаи

- Существо не может выйти за границы карты.
- Снаряд вне карты удаляется.
- Одновременная смерть обоих ульев — ничья.
- Существо с 0 радиуса не создаётся (валидация).
- Бесконечный бой предотвращается таймером.
- При расхождении хешей матч помечается `INVALID`, рейтинг не начисляется.
- При переполнении `entityId` матч невозможен (лимит 40 × 2 + снаряды < 100 000).
- При отсутствии валидных целей существо переходит в режим ожидания.
- При потере всех органов движения существо становится статичным (валидация предупреждает).

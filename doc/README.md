## 1. Аннотация

`iceja-rts` — соревновательная real-time strategy, в которой игрок не управляет армией напрямую. Игрок выступает **Архитектором**: собирает существ в биоконструкторе, задаёт им органы, характеристики и модель поведения, размещает армию перед боем — и после этого становится **Зрителем**. Существа живут, принимают решения, сражаются и умирают автономно. Победа определяется качеством конструкции, поведения и предбоевого плана, а не скоростью кликов.

Клиент — браузерное 2D-приложение (top-down), сервер — авторитетная детерминированная симуляция на Kotlin. Матч можно смотреть в реальном времени, пересматривать в виде реплея, анализировать и использовать для итераций над своими созданиями.

## 2. Ключевая формула игры

```
Лаборатория → Черновик твари → Армия → Матч → Наблюдение → Анализ → Итерация
```

Один матч длится 3–10 минут. Между матчами игрок проводит 5–30 минут в конструкторе и планировщике. Ценность игры — в цикле «придумал → собрал → выпустил → посмотрел → понял → улучшил».

## 4. Принятые решения

| № | Решение | Обоснование |
|---|---|---|
| D-01 | Сервер — Kotlin 2.x, JVM 21, Ktor 3 | Единый язык для API, симуляции и инструментов; зрелая JVM-экосистема |
| D-02 | Клиент — браузерный, 2D, top-down | Мгновенный доступ, лёгкий шаринг реплеев, не нужен движок с 3D-пайплайном |
| D-03 | Клиентский стек — TypeScript + PixiJS 8 + React 19 + Vite | Быстрый рендер 2D, гибкий UI, общие схемы данных с сервером через codegen |
| D-04 | Симуляция детерминированная, с фиксированным тиком 30 Гц | Реплеи, античит, воспроизводимость баланса, серверный авторитет |
| D-05 | Только целочисленная арифметика в симуляции | Исключение расхождений между платформами и версиями JVM |
| D-06 | Игрок не влияет на бой в реальном времени | Столп игры: автономность существ |
| D-07 | Армия фиксируется до матча, производство в ranked отсутствует | Убирает микроконтроль, уравнивает реакцию и стратегию |
| D-08 | Матч 1×1, 3–10 минут, до 40 существ на сторону | Зрелищность, предсказуемая длительность, нагрузка |
| D-09 | Модульный монолит на MVP, выделение sim-worker позже | Скорость разработки без потери границ модулей |
| D-10 | Монетизация только косметическая и QoL | Честная соревновательная среда |
| D-11 | Реплеи — детерминированная ресимуляция + снапшоты ключевых кадров | Компактность и точность |
| D-12 | Основные локали на запуске: русский, английский | Целевые рынки и размер команды |

## 6. Как читать документ

- **Продукт и гейм-дизайн**: `01`, `06`, `07`, `11`, `13`.
- **Разработка сервера**: `03`, `04`, `05`, `08`, `10`, `12`.
- **Разработка клиента**: `03`, `06`, `07`, `08`, `09`, `12`.
- **Тестирование и эксплуатация**: `02`, `12`, `13`.
- **Юридические и продуктовые риски**: `01`, `11`, `12`, `13`.

Требования имеют идентификаторы `FR-*` (функциональные) и `NFR-*` (нефункциональные). Приоритеты: **Must** — без этого нет MVP, **Should** — желательно к бетe, **Could** — после релиза. Все числовые значения в документе являются целевыми и уточняются по результатам прототипа.

## 7. Границы проекта

Входит в проект:

- серверная симуляция и API;
- браузерный 2D-клиент;
- биоконструктор и редактор поведения;
- матчмейкинг, рейтинг, реплеи;
- базовая прогрессия и косметическая монетизация;
- инструменты баланса и модерации.

Не входит в первую версию:

- мобильные приложения;
- 3D-клиент;
- пользовательские карты и моды;
- кооператив более чем 1×1;
- голосовой чат;
- кросс-платформенные аккаунты консолей.

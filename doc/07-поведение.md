# 07. Поведение и автономный ИИ

## 7.1. Назначение

Игрок задаёт не приказы, а **модель поведения**. Система должна:

- быть выразительной: позволять агрессию, осторожность, стайность, оборону, сбор ресурсов;
- быть понятной: решения объяснимы, отлаживаемы и визуализируемы;
- быть детерминированной: одинаковый граф и состояние дают одинаковое решение;
- быть ограниченной: сложность поведения входит в бюджет существа;
- не требовать программирования.

## 7.2. Слои принятия решений

```text
┌─────────────────────────────────────────────┐
│ 1. Инстинкты (жёстко зашиты органами)       │
│    дыхание, смерть, перегрев, голод         │
├─────────────────────────────────────────────┤
│ 2. Утилитарный выбор цели (Utility AI)      │
│    оценка целей и режимов                   │
├─────────────────────────────────────────────┤
│ 3. Граф поведения (Behavior Tree)           │
│    последовательности действий              │
├─────────────────────────────────────────────┤
│ 4. Исполнитель действий (Action layer)      │
│    движение, атака, сбор, способности       │
└─────────────────────────────────────────────┘
```

### 7.2.1. Инстинкты

Не редактируются игроком, но зависят от органов:

- при HP ≤ 0 — смерть;
- при перегреве — принудительное охлаждение;
- при энергии 0 — отдых;
- при пожаре — попытка уйти в воду;
- при попадании — краткий поворот к источнику (если есть сенсоры).

Инстинкты имеют приоритет выше графа, но не отменяют его полностью: они меняют доступные действия.

### 7.2.2. Utility AI

На каждом решении (10 Гц) система оценивает **режимы**:

| Режим | Условие | Приоритет |
|---|---|---|
| `SURVIVE` | HP < 25% | Максимальный |
| `REST` | Энергия < 15% | Высокий |
| `DEFEND_HIVE` | Улей под атакой | Высокий |
| `ATTACK` | Есть видимая цель | Средний |
| `HUNT` | Есть известная цель | Средний |
| `HARVEST` | Есть нектар и низкая энергия | Низкий |
| `REGROUP` | Потеря группы | Низкий |
| `PATROL` | Нет цели | Базовый |
| `IDLE` | Ничего не найдено | Минимальный |

Оценка режима:

```
score = baseWeight
      * healthFactor
      * energyFactor
      * threatFactor
      * distanceFactor
      * personalityFactor
```

- `baseWeight` задаётся графом/параметрами.
- `personalityFactor` — параметры «агрессия», «осторожность», «стайность», «жадность».
- Оценки сравниваются с гистерезисом 10%, чтобы избежать дребезга.
- При равенстве побеждает режим с меньшим индексом (детерминизм).

### 7.2.3. Граф поведения

Граф — это Behavior Tree с расширениями. Он выбирает **действия** внутри режима и задаёт условия перехода.

## 7.3. Blackboard (доска состояния)

Каждое существо имеет фиксированный набор ключей. Значения обновляются сенсорами и действиями.

| Ключ | Тип | Описание |
|---|---|---|
| `self.hpPct` | int 0–100 | Здоровье |
| `self.energyPct` | int 0–100 | Энергия |
| `self.heat` | int 0–100 | Тепло |
| `self.isStunned` | bool | Стан |
| `self.isBurning` | bool | Горение |
| `self.isFleeing` | bool | Бегство |
| `self.x`, `self.y` | int | Позиция |
| `self.role` | enum | Роль из пресета |
| `target.id` | int | Текущая цель |
| `target.distance` | int | Дистанция |
| `target.hpPct` | int | HP цели |
| `target.isRanged` | bool | Дальний бой |
| `target.threat` | int | Оценка угрозы |
| `enemy.nearestId` | int | Ближайший враг |
| `enemy.count` | int | Врагов в радиусе |
| `enemy.inVision` | bool | Видимый враг |
| `ally.count` | int | Союзников рядом |
| `ally.nearestId` | int | Ближайший союзник |
| `ally.hiveUnderAttack` | bool | Улей атакован |
| `hive.hpPct` | int | HP своего улья |

### 7.3.1. Ограничения

- Ключи фиксированы; пользовательские переменные не поддерживаются в MVP.
- Значения целочисленные.
- Обновление — в фазе Sensors.
- Память хранится 5–20 с в зависимости от органов.

## 7.4. Узлы графа

### 7.4.1. Композиты

| Узел | Поведение |
|---|---|
| `Selector` | Возвращает успех первого успешного ребёнка |
| `Sequence` | Выполняет детей по порядку, пока все успешны |
| `Parallel` | Выполняет детей одновременно, успех по политике |
| `UtilitySelector` | Выбирает ребёнка с максимальной оценкой |
| `RandomSelector` | Выбирает случайного ребёнка (детерминированный PRNG) |
| `Cooldown` | Блокирует ребёнка на N тиков после успеха |
| `Repeat` | Повторяет ребёнка N раз или до неудачи |
| `Inverter` | Инвертирует результат |
| `Subtree` | Ссылка на подграф |

### 7.4.2. Условия

| Узел | Параметры | Истина, если |
|---|---|---|
| `HasTarget` | — | Есть валидная цель |
| `TargetInRange` | `range` | Дистанция ≤ range |
| `TargetVisible` | — | Цель видима |
| `HpBelow` | `pct` | HP ≤ pct |
| `HpAbove` | `pct` | HP ≥ pct |
| `EnergyBelow` | `pct` | Энергия ≤ pct |
| `EnergyAbove` | `pct` | Энергия ≥ pct |
| `HeatAbove` | `value` | Тепло ≥ value |
| `EnemyCount` | `min`, `max`, `radius` | Количество врагов в радиусе |
| `AllyCount` | `min`, `max`, `radius` | Количество союзников |
| `IsUnderAttack` | `seconds` | Получал урон за последние N секунд |
| `HiveUnderAttack` | — | Улей атакован |
| `HiveHpBelow` | `pct` | HP улья ≤ pct |
| `EnemyHiveInRange` | `range` | Улей врага в радиусе |
| `HasStatus` | `status` | Статус активен |
| `TimerElapsed` | `seconds` | Прошло время |
| `RandomChance` | `pct` | PRNG ≤ pct |
| `ResourceNearby` | `radius` | Есть нектар |
| `CorpseNearby` | `radius` | Есть труп |
| `IsRole` | `role` | Роль совпадает |
| `HasLineOfSight` | `entity` | Есть линия видимости |

### 7.4.3. Действия

| Действие | Параметры | Результат |
|---|---|---|
| `MoveTo` | `target`, `mode` | Движение к цели |
| `MoveToPoint` | `x`, `y` | Движение в точку |
| `AttackTarget` | `target` | Атака текущей цели |
| `AttackMove` | `x`, `y` | Движение с атакой по пути |
| `Flee` | `from`, `distance` | Бегство |
| `Follow` | `allyId`, `distance` | Следование |
| `Regroup` | `radius` | Сбор группы |
| `HoldPosition` | — | Стоять |
| `Patrol` | `points[]` | Патрулирование |
| `Guard` | `point`, `radius` | Охрана точки |
| `Harvest` | `nodeId` | Сбор нектара |
| `EatCorpse` | `corpseId` | Поедание трупа |
| `UseAbility` | `abilityId`, `target` | Способность |
| `Burrow` | — | Копание |
| `Unburrow` | — | Выход |
| `Reproduce` | — | Размножение (режимы) |
| `Taunt` | `radius` | Провокация |
| `Wait` | `ticks` | Ожидание |

### 7.4.4. Параметры поведения

Глобальные параметры генома:

| Параметр | Диапазон | Влияние |
|---|---|---|
| `aggression` | 0–100 | Частота атак, дистанция преследования |
| `caution` | 0–100 | Порог отступления |
| `cohesion` | 0–100 | Держаться группы |
| `greed` | 0–100 | Приоритет ресурсов |
| `loyalty` | 0–100 | Защита улья |
| `focus` | 0–100 | Сосредоточение на одной цели |
| `adaptability` | 0–100 | Смена цели при неудаче |

Параметры влияют на веса Utility AI, но не заменяют граф.

## 7.5. Исполнение

### 7.5.1. Частота

- Решение (Utility + BT): 10 Гц, каждые 3 тика.
- Действия (движение, атака): каждый тик.
- Пересчёт пути: по необходимости, не чаще 1 раза в 0.5 с.
- Проверка цели: каждые 3 тика.

### 7.5.2. Детерминизм

- Узлы выполняются в порядке индексов.
- `RandomSelector` использует поток `ai` с seed существа.
- При равных оценках — меньший `nodeId`.
- Таймеры считаются в тиках.
- Никаких строковых сравнений в горячем цикле.

### 7.5.3. Отказ и повтор

- Действие может вернуть `SUCCESS`, `FAILURE`, `RUNNING`.
- `RUNNING` сохраняется между тиками.
- При `FAILURE` родитель решает, что делать.
- Защита от бесконечных циклов: лимит 200 переходов на решение, затем `FAILURE`.
- Защита от «дребезга»: минимальное время удержания действия 0.5 с, кроме аварийных.

### 7.5.4. Приоритеты

1. Инстинкты (смерть, стан, перегрев).
2. `SURVIVE` (бегство/лечение).
3. `DEFEND_HIVE`.
4. `ATTACK`/`HUNT`.
5. `HARVEST`/`SCAVENGE`.
6. `REGROUP`.
7. `PATROL`.
8. `IDLE`.

## 7.6. Редактор поведения

### 7.6.1. Раскладка

```text
┌──────────────────────────────────────────────────────────────┐
│ Топбар: имя, пресет, сохранить, проверить, тест              │
├───────────────┬──────────────────────────────┬───────────────┤
│ Палитра узлов │  Граф (React Flow)           │ Инспектор     │
│ поиск         │  зум, миникарта, группы      │ параметры     │
│ категории     │  связи, комментарии          │ подсказки     │
├───────────────┴──────────────────────────────┴───────────────┤
│ Сложность: 24 / 100 CP   Ошибки: 1   Предупреждения: 2       │
└──────────────────────────────────────────────────────────────┘
```

### 7.6.2. Взаимодействие

- Перетаскивание узлов из палитры.
- Соединение портов: выход → вход.
- Двойной клик — переименование/параметры.
- ПКМ — контекстное меню.
- Выделение рамкой, копирование, вставка.
- Группы и комментарии.
- Автосохранение черновика раз в 30 секунд.
- Undo/redo.

### 7.6.3. Валидация

| Код | Условие |
|---|---|
| `NO_ROOT` | Нет корневого узла |
| `MULTIPLE_ROOTS` | Несколько корней |
| `ORPHAN_NODE` | Узел не связан с корнем |
| `CYCLE` | Цикл в графе |
| `INVALID_PORT` | Несовместимые порты |
| `MISSING_PARAM` | Не задан обязательный параметр |
| `OUT_OF_RANGE` | Параметр вне диапазона |
| `TOO_DEEP` | Глубина > 8 |
| `TOO_MANY_NODES` | Узлов > 64 |
| `TOO_COMPLEX` | CP > 100 |
| `UNKNOWN_SUBTREE` | Ссылка на несуществующий подграф |
| `DANGLING_ACTION` | Действие без цели и без способа её получить |

### 7.6.4. Стоимость сложности

| Элемент | CP |
|---|---|
| Композит | 2 |
| Условие | 1 |
| Действие | 2 |
| Параметр с несколькими режимами | +1 |
| Подграф | 3 + CP подграфа |
| Комментарий | 0 |

Стоимость в BM: `behaviorCp * 2`.

### 7.6.5. Отладка

- Запуск на полигоне с оверлеем.
- Подсветка активного узла.
- Панель blackboard.
- Лог решений: тик, режим, узел, цель, причина.
- Пауза и пошаговое выполнение (только полигон).
- «Почему я не атакую?» — объяснение: нет цели / вне радиуса / нет энергии / стан.

## 7.7. Пресеты поведения

### 7.7.1. Берсерк

```text
UtilitySelector
  SURVIVE: HpBelow(20) → Flee(from=target, distance=15)
  ATTACK: HasTarget → AttackTarget
  HUNT: EnemyCount(min=1, radius=30) → MoveTo(enemy.nearest)
  PATROL: → Patrol
```

Параметры: aggression 90, caution 10, cohesion 20, focus 80.

### 7.7.2. Страж

```text
UtilitySelector
  SURVIVE: HpBelow(15) → MoveToPoint(hive)
  DEFEND: HiveUnderAttack → AttackTarget(enemy.nearest)
  ATTACK: TargetInRange(12) → AttackTarget
  GUARD: → Guard(point=hive, radius=15)
```

Параметры: aggression 40, caution 50, loyalty 90.

### 7.7.3. Стайный охотник

```text
UtilitySelector
  SURVIVE: HpBelow(25) → Regroup
  ATTACK: EnemyCount(min=1) → Sequence[
      Follow(ally.nearest, 5),
      AttackTarget
  ]
  HUNT: → MoveTo(enemy.nearest)
  REGROUP: AllyCount(max=0, radius=10) → MoveTo(ally.nearest)
  PATROL: → Patrol
```

Параметры: aggression 60, caution 40, cohesion 90.

### 7.7.4. Падальщик

```text
UtilitySelector
  SURVIVE: HpBelow(20) → Flee
  SCAVENGE: CorpseNearby(20) → EatCorpse
  HARVEST: ResourceNearby(20) → Harvest
  ATTACK: TargetInRange(3) and HpAbove(50) → AttackTarget
  PATROL: → Patrol
```

Параметры: aggression 20, caution 70, greed 90.

### 7.7.5. Осадный червь

```text
UtilitySelector
  SIEGE: EnemyHiveInRange(30) → AttackTarget(enemyHive)
  ATTACK: TargetInRange(2) → AttackTarget
  MOVE: → MoveTo(enemyHive)
```

Параметры: aggression 70, caution 20, focus 100.

## 7.9. Объяснимость

Каждое решение должно иметь причину, доступную игроку:

```json
{
  "tick": 3120,
  "mode": "ATTACK",
  "nodeId": "n7",
  "action": "AttackTarget",
  "targetId": 42,
  "reason": "TARGET_IN_RANGE",
  "scores": {
    "SURVIVE": 12,
    "ATTACK": 78,
    "HUNT": 40,
    "PATROL": 10
  }
}
```

Причины:

- `TARGET_IN_RANGE`
- `TARGET_VISIBLE`
- `NO_TARGET`
- `LOW_HP`
- `LOW_ENERGY`
- `HIVE_UNDER_ATTACK`
- `NO_PATH`
- `COOLDOWN`
- `STUNNED`
- `OUT_OF_RANGE`
- `BEHAVIOR_FALLBACK`

## 7.10. Ограничения и крайние случаи

- Граф без действия `AttackTarget` не атакует, даже если есть оружие.
- Граф без `MoveTo` не двигается, даже если есть ноги.
- При отсутствии цели действия `AttackTarget` возвращает `FAILURE`.
- При отсутствии пути `MoveTo` возвращает `FAILURE` и запускает пересчёт.
- При стане все действия, кроме инстинктов, возвращают `FAILURE`.
- При смерти граф не исполняется.
- При потере сенсоров цели сбрасываются, но память сохраняется.
- При смене цели кулдаун атаки не сбрасывается.
- При `RandomChance` используется отдельный поток, чтобы не влиять на другие решения.
- Граф не может содержать пользовательский код, сетевые вызовы или файловые операции.
- Максимальное время выполнения решения — 0.2 мс на существо; при превышении — упрощение (fallback).
- Поведение не может читать состояние, не входящее в blackboard.

## 7.11. Будущее развитие

- GOAP-планировщик для сложных последовательностей.
- Пользовательские переменные и счётчики.
- Обучение на реплеях (офлайн, без влияния на детерминизм).
- Кооперативные графы для группы существ.
- Обмен графами через код-ссылку.
- Голосовые/текстовые описания, превращаемые в граф с подтверждением.

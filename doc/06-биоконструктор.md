# 06. Биоконструктор

## 6.1. Назначение

Биоконструктор — центральная механика игры. Игрок собирает существо из **шасси**, **органов** и **улучшений**, задаёт ему **поведение** и получает законченный геном, который можно сохранить, протестировать и добавить в армию.

Конструктор должен одновременно:

- быть понятным новичку за 10 минут;
- давать опытному игроку пространство для оптимизации;
- быть полностью детерминированным и серверно-валидируемым;
- объяснять последствия каждого решения.

## 6.2. Модель генома

### 6.2.1. Состав

```text
Genome
  schemaVersion
  chassisId
  sizeClass
  parts[]
    partId
    socketId
    offset {x, y}
    rotation
    scale
    mirrored
    parameters{}
  upgrades[]
    stat
    level
  behavior
    graph
    parameters
  palette
  name
  metadata
```

### 6.2.2. Ограничения

- Геном неизменяем после сохранения; правка создаёт новую версию.
- Геном ссылается на `catalogVersion` и `rulesetVersion`.
- Хеш генома входит в хеш матча.
- Имя существа — 3–24 символа, проходит фильтр.
- Палитра — из открытых наборов, не влияет на бой.

### 6.2.3. Сокеты

Сокеты задаются шасси. В 2D top-down используются:

| Сокет | Назначение | Количество |
|---|---|---|
| `CORE` | Ядро, сердце, мозг | 1–2 |
| `FRONT` | Голова, челюсти, глаза | 1–2 |
| `BACK` | Хвост, железы, двигатели | 1–2 |
| `LEFT` | Парные конечности, оружие | 1–3 |
| `RIGHT` | Парные конечности, оружие | 1–3 |
| `TOP` | Спина, броня, аура | 1–2 |
| `UNDER` | Брюхо, копание, захват | 1 |

- Каждый орган требует тип сокета.
- Парные сокеты поддерживают зеркалирование.
- Смещение внутри сокета ограничено радиусом (0.2–0.6 м).
- Пересечение спрайтов не запрещено, но валидатор предупреждает о «каше».

### 6.2.4. Шасси

| ID | Класс | Масса, кг | HP | Сокеты | Стоимость | Особенность |
|---|---|---|---|---|---|---|
| `GRUB` | S | 20 | 80 | 4 | 40 | Дешёвое, хрупкое |
| `CRAWLER` | S | 30 | 100 | 8 | 60 | Универсальное |
| `BRUTE` | M | 120 | 300 | 10 | 120 | Много HP, медленное |
| `TITAN` | L | 400 | 900 | 12 | 240 | Осадное, дорогое |
| `FLYER` | S | 40 | 120 | 8 | 100 | Игнорирует часть препятствий |
| `BURROWER` | M | 150 | 350 | 8 | 140 | Может копать |
| `STATIC` | M | 200 | 600 | 4 | 160 | Не двигается, только особые режимы |

Колонка «Сокеты» — общее количество точек крепления. Зеркальный парный орган занимает две точки. Распределение по типам сокетов задаётся шасси и не может превышать общий лимит.

Ограничения массы шасси:

| Класс | Комфортная масса | Жёсткий предел |
|---|---|---|
| S | ≤ 80 кг | 150 кг |
| M | ≤ 300 кг | 700 кг |
| L | ≤ 1200 кг | 2500 кг |

Превышение комфортной массы: −10% скорости за каждые 20%. Превышение жёсткого предела: ошибка валидации.

Все значения — базовые, до улучшений и модификаторов. Стоимость указана в BM. Масса — в кг. HP — прибавка к максимуму. Энергия — вклад в максимум/регенерацию. Контроль — нагрузка на нервную систему.

## 6.4. Улучшения характеристик

Игрок может вкладывать BM в улучшения. Каждый уровень стоит всё дороже.

| Улучшение | Эффект за уровень | Базовая цена | Рост цены | Макс. уровень |
|---|---|---|---|---|
| `HP` | +8% базового HP | 15 | ×1.35 | 5 |
| `DAMAGE` | +6% урона | 20 | ×1.40 | 5 |
| `ARMOR` | +8 брони | 15 | ×1.35 | 5 |
| `SPEED` | +4% скорости | 20 | ×1.40 | 4 |
| `ENERGY` | +10% энергии | 12 | ×1.30 | 5 |
| `ACCURACY` | +5 точности | 18 | ×1.40 | 4 |
| `CONTROL` | +8 контроля | 15 | ×1.35 | 4 |

Формула цены уровня:

```
price(level) = round(base * growth^(level - 1))
```

Суммарная цена улучшений входит в стоимость существа. Улучшения не могут превышать 40% стоимости существа.

## 6.5. Производные характеристики

### 6.5.1. Масса

```
mass = chassis.mass + Σ(part.mass * (mirrored ? 2 : 1)) + Σ(upgrade.mass)
```

### 6.5.2. Максимальное HP

```
maxHp = chassis.hp
      + Σ(part.hp)
      + hpUpgradeLevel * round(chassis.hp * 0.08)
      + round(mass * 0.5)
```

### 6.5.3. Тяга и скорость

```
traction = Σ(part.traction) * (1 + speedUpgradeLevel * 0.04)
vmax = clamp(0.5, 8.0, traction / mass * 2.0)          // м/с
accel = clamp(2.0, 20.0, traction / mass * 8.0)        // м/с²
turnRate = clamp(90, 720, control / mass * 720)        // °/с
```

Модификаторы поверхности и статусов применяются к `vmax` на каждом тике.

### 6.5.4. Контроль

```
controlCapacity = Σ(part.control) + controlUpgradeLevel * 8
controlLoad = Σ(part.controlCost) + Σ(weapon.complexity) + behaviorCp * 0.5
```

Если `controlLoad > controlCapacity`:

```
excess = controlLoad - controlCapacity
decisionPenaltyTicks = min(5, ceil(excess / 10))
```

Штраф увеличивает интервал принятия решений. При `excess > 50` — ошибка валидации.

### 6.5.5. Энергия

```
maxEnergy = Σ(part.energy) + energyUpgradeLevel * round(baseEnergy * 0.10)
regen = Σ(part.regen)
upkeep = mass * 0.02 + Σ(weapon.idleDrain) + brainUpkeep
```

`brainUpkeep = 0.5 + behaviorCp * 0.02`.

Если `regen - upkeep ≤ 0` — предупреждение. Если `< -5` — ошибка.

### 6.5.6. Тепло

```
heatGen = Σ(weapon.heat) + sprintHeat + metabolicHeat
cooling = 10 + Σ(part.cooling) + mass * 0.02
```

- Тепло накапливается: `heat += heatGen - cooling` за секунду.
- При `heat ≥ 100`: перегрев, −50% скорости, дальние атаки недоступны, пока `heat < 40`.
- Тепло не может быть отрицательным.

### 6.5.7. Броня

```
armor[type] = min(200, Σ(part.armor[type]) + armorUpgradeLevel * 8)
```

Снижение урона:

```
reduction = armorEff / (armorEff + 100)
```

### 6.5.8. Урон и DPS

```
cycleTime = max(0.3, weapon.cooldown)
hitChance = accuracy / (accuracy + targetEvasion)
dps = Σ(weapon.damage * hitChance / cycleTime)
```

В интерфейсе показывается DPS против трёх профилей брони: 0, 50, 100.

### 6.5.9. Эффективное HP

```
effectiveHp = maxHp / (1 - averageReduction)
averageReduction = mean(reduction[type] for type in damageTypes)
```

### 6.5.10. Стоимость

```
cost = chassis.cost
     + Σ(part.cost * (mirrored ? 2 : 1))
     + Σ(upgrade.cost)
     + behaviorCp * 2
     + round(mass * 0.05)
```

Ограничения:

- Стоимость существа: 300–3000 BM.
- Стоимость армии: ≤ 6000 BM.
- Количество существ: ≤ 40.

## 6.6. Валидация

### 6.6.1. Ошибки (блокируют сохранение)

| Код | Условие |
|---|---|
| `NO_CHASSIS` | Не выбрано шасси |
| `NO_BRAIN` | Нет мозга |
| `MULTIPLE_BRAINS` | Больше одного мозга |
| `NO_METABOLISM` | Нет сердца/реактора |
| `NO_LOCOMOTION` | Нет локомоции для нестатичного шасси |
| `STATIC_LOCOMOTION` | Статичное шасси с локомоцией |
| `SOCKET_MISMATCH` | Орган не подходит к сокету |
| `SOCKET_OCCUPIED` | Сокет занят |
| `MASS_LIMIT` | Превышен жёсткий предел массы |
| `BUDGET_EXCEEDED` | Стоимость > 3000 BM |
| `ENERGY_NEGATIVE` | Энергобаланс < −5 |
| `CONTROL_OVERLOAD` | Превышение контроля > 50 |
| `INVALID_BEHAVIOR` | Ошибка графа поведения |
| `INVALID_PART_VERSION` | Орган недоступен или устарел |
| `INVALID_NAME` | Имя не проходит фильтр |

### 6.6.2. Предупреждения (не блокируют)

| Код | Условие |
|---|---|
| `LOW_HP` | HP < 100 |
| `LOW_DPS` | DPS < 10 |
| `NO_SENSORS` | Нет сенсоров |
| `NO_WEAPON` | Нет оружия |
| `ENERGY_TIGHT` | Энергобаланс < 2 |
| `OVERWEIGHT` | Масса выше комфортной |
| `ASYM_LIMBS` | Несимметричные конечности |
| `SLOW_TURN` | Поворот < 120°/с |
| `OVERHEAT_RISK` | Тепло > охлаждения |
| `BEHAVIOR_TOO_SIMPLE` | < 5 узлов |
| `BEHAVIOR_TOO_COMPLEX` | > 80 CP |

### 6.6.3. Подсказки (info)

- «Добавьте сенсоры, иначе существо не найдёт врага».
- «Нектарный зоб окупится, если бой длится дольше 3 минут».
- «Костяные пластины снижают урон кинетики на 20%».
- «Ваша армия на 80% состоит из ближнего боя».

### 6.7.1. Раскладка


### 6.7.2. Сцена

- Ортографическая камера, зум 0.5–3×.
- Фон — сетка лаборатории, нейтральный.
- Существо в центре, поворот мышью с зажатой средней кнопкой.
- Сокеты подсвечиваются при перетаскивании органа.
- Допустимые сокеты — зелёные, недопустимые — красные.
- Тени и лёгкая анимация дыхания для живости.
- Переключение «вид сверху / схема» (схема показывает сокеты и зоны).

### 6.7.3. Каталог

- Категории: ядро, локомоция, сенсоры, ближний бой, дальний бой, защита, утилиты, улучшения.
- Фильтры: доступно, цена, роль, тип урона.
- Поиск по названию и тегам.
- Карточка: иконка, название, цена, масса, ключевые статы, краткое описание, кнопка «Добавить».
- Заблокированные органы показываются с условием открытия.
- Наведение на карточку показывает сравнение с текущим органом в слоте.

### 6.7.4. Панель характеристик

- Крупно: HP, DPS, скорость, масса, стоимость.
- Энергобаланс: полоса «регенерация vs расход».
- Тепло: полоса и прогноз перегрева.
- Контроль: загрузка/ёмкость.
- Броня по типам: таблица.
- Эффективное HP и время до смерти против типового DPS.
- Кнопка «Сравнить с шаблоном».

### 6.7.5. Бюджет

- Полоса бюджета с цветами: зелёный ≤ 80%, жёлтый 80–100%, красный > 100%.
- При превышении сохранение блокируется, показывается, что убрать.
- Подсказка «самый дорогой орган».

### 6.7.6. Валидация

- Панель снизу, сгруппированная по серьёзности.
- Клик по ошибке подсвечивает орган/сокет.
- Ошибки не скрываются при сохранении; сервер повторяет проверку.
- Предупреждения можно игнорировать, но они сохраняются в метаданных.

### 6.7.7. Взаимодействие

| Действие | Мышь | Клавиатура |
|---|---|---|
| Добавить орган | Drag из каталога в сокет | Enter на карточке |
| Удалить | ПКМ → удалить | Delete |
| Повернуть | Колесо с Alt | `[` / `]` |
| Симметрия | Кнопка | `S` |
| Undo | Кнопка | Ctrl+Z |
| Redo | Кнопка | Ctrl+Shift+Z |
| Зум | Колесо | `+` / `-` |
| Тест | Кнопка | Ctrl+Enter |
| Сохранить | Кнопка | Ctrl+S |

### 6.7.8. Превью и тест

- Кнопка «Тест» запускает полигон с текущим геномом (без сохранения).
- Полигон — серверная симуляция против бота-манекена.
- Доступны пауза, скорость 0.5/1/2/4, отладочные оверлеи.
- Результат теста не влияет на рейтинг и экономику.
- Можно сохранить тестовый геном как черновик.

## 6.11. Ограничения и крайние случаи

- Нельзя сохранить геном с органом, который был удалён из каталога; версия остаётся доступной для старых матчей.
- Импорт генома с другой версией каталога конвертируется с предупреждением.
- Имя существа не может содержать ссылки, HTML, оскорбления.
- Палитра не влияет на видимость в тумане войны.
- Слишком маленькое существо (радиус < 0.2 м) не создаётся.
- Слишком большое (радиус > 1.5 м) не проходит валидацию.
- Существо без оружия допустимо, но получает предупреждение.
- Существо без сенсоров допустимо, но не может активно искать цели.
- Статичное шасси допустимо только в режимах «Осада» и «Песочница».
- Максимальное количество органов — 24 (визуальная читаемость).
- Максимальная глубина поведения — 8, узлов — 64.

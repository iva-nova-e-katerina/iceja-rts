# 10. Данные и хранилища

## 10.1. Общие принципы

- PostgreSQL — источник истины для аккаунтов, контента, результатов и экономики.
- Redis — эфемерное состояние: сессии, очередь, реестр матчей, лимиты, pub/sub.
- S3/MinIO — файлы: реплеи, аватары, экспорты, архивы.
- CDN — статические ассеты клиента.
- Все идентификаторы — UUIDv7, кроме внутренних числовых.
- Время — `timestamptz` в UTC.
- Деньги и валюта — целые числа в минимальных единицах, без `float`.
- JSONB — только для гибких структур (геном, поведение, снапшот армии), с валидацией на входе.
- Миграции — только вперёд, обратная совместимость на одну версию.

### 10.2.1. Пользователи и доступ

```sql
create table users (

);

create table sessions (
  id uuid primary key,
  user_id uuid not null references users(id),
  refresh_hash text not null,
  user_agent text,
  ip_hash text,
  created_at timestamptz not null default now(),
  expires_at timestamptz not null,

create table email_tokens (
  id uuid primary key,
  user_id uuid not null references users(id),
  kind text not null,
  token_hash text not null,
  expires_at timestamptz not null,
  used_at timestamptz
);

create table user_settings (
  user_id uuid primary key references users(id),
  graphics jsonb not null default '{}',

```

Индексы:

- `users(email)`, `users(nickname)`, `users(status)`.
- `sessions(user_id, expires_at)`, `sessions(refresh_hash)`.
- `email_tokens(token_hash)`.

```sql

  match_id uuid primary key references matches(id),
  payload jsonb not null,
  checksum text not null,
  created_at timestamptz not null default now()

create table ratings (
  user_id uuid not null references users(id),
  mode text not null,
  season_id uuid,
  rating int not null default 1500,
  rd int not null default 350,

  id uuid primary key,

```

Партиционирование:

- `matches` по месяцу `created_at`.
- `match_players` по `match_id` через хеш или наследование.

Индексы:

- `matches(created_at desc)`, `matches(status)`.
- `match_players(user_id, match_id)`.
- `ratings(mode, rating desc)`.

- Покупки проходят через провайдера и вебхук с подписью.

### 10.2.9. Ограничения целостности

- `users.email` и `users.nickname` уникальны без учёта регистра (`citext`).
- `creature_versions` уникальны по `(creature_id, version)`.
- `army_items` уникальны по `(army_id, slot)`.
- `match_players` уникальны по `(match_id, side)`.
- `wallet_transactions.idempotency_key` уникален.
- `replay_shares.id` — случайный, не менее 12 символов.
- Каскадное удаление только для пользовательских данных; финансовые записи анонимизируются.

## 10.3. Redis

### 10.3.1. Ключи

| Ключ | Тип | TTL | Назначение |
|---|---|---|---|
| `sess:{sessionId}` | hash | 30 дней | Сессия, денлист токенов |
| `mm:queue:{region}:{mode}` | zset | — | Очередь по рейтингу |
| `mm:player:{userId}` | string | 5 мин | Текущая очередь |
| `match:{matchId}` | hash | 2 ч | Реестр матча |
| `match:{matchId}:spectators` | set | 2 ч | Зрители |
| `match:{matchId}:keyframes` | list | 2 ч | Ключевые кадры |
| `match:{matchId}:chat` | list | 2 ч | Последние сообщения |
| `worker:{workerId}:slots` | hash | 30 с | Слоты воркера |
| `worker:{workerId}:heartbeat` | string | 15 с | Heartbeat |
| `rl:{scope}:{id}` | string | окно | Rate limit |
| `idem:{key}` | string | 24 ч | Идемпотентность |
| `presence:{userId}` | string | 60 с | Онлайн |
| `sched:lock` | string | 15 с | Лидер-лок планировщика |

### 10.3.2. Pub/Sub

- Канал `match:{matchId}:snapshots` — бинарные снапшоты.
- Канал `match:{matchId}:events` — события.
- Канал `match:{matchId}:control` — старт/стоп/реконнект.
- Gateway подписывается на каналы активных матчей.
- Для 50 зрителей достаточно одного канала; при росте — отдельный fanout.

### 10.3.3. Очередь

- Элемент zset: `userId`, score = rating.
- Дополнительные данные — в `mm:player:{userId}` (armyId, mode, enqueuedAt, budget).
- Подбор атомарный через Lua-скрипт: найти пару, удалить, создать матч.
- Таймауты и боты — отдельный цикл.

### 10.3.4. Ограничения

- Redis не хранит авторитетные результаты матчей.
- При потере Redis активные матчи продолжаются, но реестр теряется; gateway восстанавливает по heartbeat.
- Все ключи имеют префикс окружения: `prod:`, `staging:`.

## 10.4. S3 / объектное хранилище

### 10.4.1. Структура

```text
s3://iceja/
  replays/{yyyy}/{mm}/{matchId}.iceja-replay.zst
  avatars/{userId}/{hash}.webp
  exports/{userId}/{creatureId}.json
  telemetry/{yyyy}/{mm}/{dd}/{shard}.parquet
  backups/{env}/{yyyy}/{mm}/{dd}/
  maps/{mapId}/{version}/...
```

### 10.4.2. Политики

- Реплеи: приватные по умолчанию, публичные через подписанные ссылки.
- Аватары: публичное чтение через CDN.
- Экспорты: приватные, TTL 7 дней.
- Бэкапы: отдельный бакет, версионирование, блокировка удаления.
- Шифрование: SSE-S3 или SSE-KMS.

### 10.4.3. Жизненный цикл

| Объект | Хранение |
|---|---|
| Ranked-реплеи | 90 дней |
| Избранные реплеи | Бессрочно |
| Турнирные реплеи | 1 год |
| Аватары | До удаления аккаунта |
| Экспорты | 7 дней |
| Бэкапы | 30 дней ежедневные, 12 месяцев месячные |
| Телеметрия | 13 месяцев агрегаты |

## 10.5. Миграции

- Flyway, версионированные файлы `V1__init.sql`, `V2__...`.
- Миграции проверяются в CI на пустой БД и на копии прод-схемы.
- Долгие операции — через `CREATE INDEX CONCURRENTLY`, батчи.
- Откат — только через новую миграцию, не через `undo`.
- Приложение совместимо с предыдущей версией схемы в течение релиза.

## 10.6. Бэкапы и восстановление

| Параметр | Значение |
|---|---|
| WAL-архивирование | Непрерывно, RPO ≤ 5 мин |
| Полный бэкап | Ежедневно, 03:00 UTC |
| Хранение | 30 дней ежедневные, 12 месяцев месячные |
| Тест восстановления | Ежемесячно на staging |
| RTO | ≤ 60 мин |
| Шифрование | Обязательно |
| Регион копии | Другой AZ/регион |

Восстановление:

1. Развернуть новый инстанс.
2. Восстановить базовый бэкап.
3. Применить WAL до точки.
4. Проверить целостность (counts, checksums).
5. Переключить трафик.
6. Уведомить пользователей при потере данных.

## 10.7. Согласованность

- Запись результатов матча — транзакция: `matches`, `match_players`, `ratings`, `wallet_transactions`, `replay`.
- Если транзакция не удалась — повтор с идемпотентным ключом.
- Рейтинг и награды не начисляются дважды.
- Чтение статистики может быть eventual consistent (read replica).
- Кэш каталога инвалидируется по версии.

## 10.8. Приватность данных

| Данные | Хранение | Доступ |
|---|---|---|
| Email | Пока аккаунт активен | Владелец, поддержка |
| Пароль | Хеш Argon2id | Никто |
| IP | Хеш, 30 дней | Безопасность |
| User-Agent | 30 дней | Безопасность |
| Матчи | 1 год | Владелец, агрегаты |
| Реплеи | 90 дней | Участники, шаринг |
| Чат | 30 дней | Модерация |
| Аналитика | 13 месяцев | Продукт, обезличено |

Удаление аккаунта:

1. Пометить `deleted_at`.
2. Анонимизировать email, ник, аватар.
3. Удалить сессии, токены, настройки.
4. Сохранить финансовые записи в анонимизированном виде.
5. Удалить реплеи с участием, кроме турнирных (по правилам).
6. Завершить в течение 30 дней.

## 10.9. Аналитические хранилища

- Сырые события — в ClickHouse (или Postgres на MVP).
- Агрегаты — в Postgres/materialized views.
- Партиционирование по дате.
- Доступ через BI-инструмент с ролями.
- Персональные данные не попадают в аналитику.

## 10.10. Оценка объёмов

| Данные | На 1 матч | На 1 000 матчей/день | На год |
|---|---|---|---|
| Метаданные матча | ~2 КБ | 2 МБ | 730 МБ |
| Реплей (сжатый) | ~150 КБ | 150 МБ | 55 ГБ |
| События | ~20 КБ | 20 МБ | 7 ГБ |
| Телеметрия | ~5 КБ | 5 МБ | 1.8 ГБ |
| Геномы | ~8 КБ | — | Зависит от пользователей |

При 10 000 матчей/день: ~550 ГБ реплеев в год; ретеншн 90 дней снижает до ~135 ГБ.

## 10.11. Проверки целостности

- Ежедневная сверка: сумма транзакций = баланс кошелька.
- Проверка «осиротевших» реплеев.
- Проверка матчей без результата старше 1 часа.
- Проверка дубликатов наград по идемпотентности.
- Алерт при расхождении > 0.01%.
- Скрипт восстановления баланса по журналу.
